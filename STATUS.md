Updated at 2026-11-25 23:21

AtPath 1.11.0 adds **Protect tables from reformatting**, on by default: tables in Live Preview are read-only, so Obsidian no longer pads their Markdown when a cell is clicked, the cursor crosses them, or a script rewrites the open note. It also fixes a click on an AtPath link inside a table writing that table into the linked note. Earlier releases cover repository links, GitHub links, exact local token counts, context copying, the compact **Copy path** menu and file-symlink shortcuts. The [README](/README.md) provides ZIP installation and a visual quick-start; release notes: [1.11.0](/docs/releases/1.11.0.md), [1.10.1](/docs/releases/1.10.1.md).

## Verified

- 244 Node tests and build pass. Table guard tests cover table detection from the syntax tree and, after a reload, from the text; cursor redirection and its direction; the switch into Live Preview; reloads; the cursor a typed table is left with; pointer, button and drag blocking; keyboard focus after a blocked press; listener cleanup; the setting toggle; the stylesheet's selector strength; and the build leaving `@codemirror/language` to Obsidian.
- Installed in Obsidian 1.15.1 on macOS, the table guard was probed with real mouse and keyboard input on a compact table, with the window made to count as focused (Obsidian's table editor only acts then). 29 interactions with the setting on: hover, click, double-click, right-click, clicks beside the table, AtPath, Markdown, wiki and external links, another plugin's table button, the add-row and add-column buttons, arrow keys from all four sides, Shift+arrow and mouse-drag selections, programmatic cursor and selection jumps, in-note search, the switch from Source mode, pasting, typing and **Insert table**. All 29 left the table as written and every link opened.
- 16 further scenarios, taken from two independent code reviews and each first reproduced as a failure: a selection collapsed into a table (Shift+arrow, mouse drag, select all), notes that begin or end with a table, a jump into a table at the end of a 5,000-line note, a click on a table in another pane followed by typing, a note rewritten on disk while open, text dragged over and dropped onto a cell, a table typed key by key, and undo. 14 left every table as written; the typed table ended exactly as it does with the setting off; undo is the gap listed below.
- With the setting off, on the same build: a click, arrow keys, the add-row button, the switch from Source mode, a collapsed selection, a note that begins with a table, a note rewritten on disk and a dropped text each pad the table. So the setting restores Obsidian's table editor without a reload, and the probes above would have caught a missing guard.
- A cursor sweep over every line of a note with tables in quotes, lists, callouts and code blocks turned the cursor away from the lines of rendered tables only, and rewrote nothing. In a popout window, with events sent by script, the press was stopped, the add button hidden and the cursor kept out.
- AtPath links inside a table: with the setting off, 5 of 5 clicks and 3 of 3 Cmd+clicks opened the link and rewrote neither note; before the fix, 4 of 4 clicks overwrote part of the linked note.
- From 1.10.x, on the installed build: **as GitHub link** in **Copy path** for files, folders, a two-item selection and the command; the compact menu and its setting; physical drags of a file and a folder into TextEdit.
- From 1.9.0, installed acceptance checked 948 folder totals and exclusion breakdowns against 4,886 indexed files, plus 28 visible explorer badges. Exact counts matched Python tiktoken for 4,423 files; offline same-size/same-timestamp edits invalidate the cache.
- The tag-triggered release workflow tests and builds, checks version consistency and committed bundle identity, and packages only main.js, manifest.json and styles.css in an atpath folder. It does not overwrite existing releases.

## Verification limits

- The table guard was tested only on macOS desktop. Mobile was not tested: the touch and pen handling, the press on a table while one of its cells is being edited, and controls inside cells are covered by unit tests only. Popout windows were probed only with scripted events, and the right-click table menu was checked as an event, not on screen.
- Table guard gaps: undo or redo that returns the cursor into a table opens Obsidian's table editor; typing a table in Live Preview behaves as with the setting off, so Obsidian can take it over and pad it; **Insert table** leaves the cursor below the new table; a table that ends the note cannot be passed with the keyboard.
- The table guard depends on the internal names `cm-table-widget`, `HyperMD-table-row`, `table-row-btn` and `table-col-btn`, a `cm-editor` nested in a table, the `set` user event of a reload, and the internal effect that sets the Live Preview field; see [docs/reference.md](/docs/reference.md#tables-in-live-preview).
- Drag-out was tested only on macOS with TextEdit as the target; multi-selection drags were checked through dispatched events, not a physical drag. Popout windows are not covered by the drag listeners.
- Real-device mobile/Sync and live publication remain untested. Native integration and the **Copy path** submenu placement use internal Obsidian APIs.
