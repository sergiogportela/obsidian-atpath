# AtPath 1.11.1

Moving or archiving a repository preserves links that still point to the correct target.

## Fixed

- Moving a whole checkout could unnecessarily rewrite link destinations, turning readable accents such as `segmentação.md` into `segmenta%C3%A7%C3%A3o.md`. AtPath now checks the destination against the new repository map and preserves its exact spelling when it still reaches the intended target.
- This also preserves incoming GitHub links, links inside nested repositories, Markdown escapes and existing percent-encoding. Notes with no required changes are not written.
- Genuine file renames and moves between repositories still update destinations. Labels, titles, query strings and fragments stay intact; intentional commit-SHA links stay unchanged.

Existing encoded links remain valid and are not converted back automatically. Native wikilinks and image embeds continue to follow Obsidian’s own link-update behavior.

## Install

Requires **Obsidian 1.15 or newer**.

Download **atpath-1.11.1.zip** and extract its `atpath` folder into your vault’s `.obsidian/plugins/` folder, or your configured settings folder. Enable AtPath in **Settings → Community plugins**.

Already installed? Replace only `main.js`, `manifest.json` and `styles.css`, keep `data.json`, then reload AtPath or restart Obsidian. BRAT users can update `sergiogportela/obsidian-atpath`.

## Validation

- All 250 automated tests pass, including six new regression tests for preserving destinations and avoiding unnecessary writes.
- Tested through Obsidian 1.15.1 on macOS: moving a checkout containing a nested repository preserved all seven fixture files byte for byte, with unchanged modification times and zero modify events. All nine links resolved after the move.
- Moving a source note into another repository and renaming an accented target still updated the required links correctly. Mobile and other operating systems were not tested for this fix.
